# 常用提示词模板集

MCP 配好后，"怎么说"直接决定机器人做得对不对。这里汇集了经过实测的提示词模板，你可以直接复制，或按自己习惯改写。

> 核心原则：说清楚目标 + 强调复核 + 给出边界。机器人没有每步完成回报，所以复杂任务里要明确告诉 AI「用 `robot_status` 确认后再继续」。

## 一、单步简单指令

日常使用不需要复杂提示词，直接描述需求即可：

- 「帮我看看机器人电量和当前在做什么」
- 「让机器人说：欢迎回家」
- 「拍一张现在的照片给我」
- 「录一段 10 秒的视频」
- 「把音量调到 50」
- 「让机器人回去充电」

## 二、导航 + 拍照（顺序执行）

```
去客厅看看当前情况。要求：
1. 先用 robot_list_locations 确认地图里有没有"客厅"，没有就告诉我，不要猜地点
2. 用 robot_navigate 导航过去，然后用 robot_status 确认任务已启动/抵达
3. 确认后再用 robot_take_photo 拍照，把照片发给我
4. 每一步都确认完成后再进入下一步，不要连续下发
```

## 三、叫早 / 检测人（带上限的循环）

```
去客厅循环叫早，直到检测到人：
1. 先 robot_list_locations 确认"客厅"存在
2. 循环：robot_speak 说"起床啦"，等25秒，robot_status 检查"当前检测到人数"和视野
3. 人数>0 或视野有人 → 停止循环；否则最多重复10轮
4. 10轮仍无人 → 不要继续，直接回去充电并告诉我"叫早10轮未检测到人"
5. 每轮都要用 robot_status 复核，不要凭返回 OK 判断
```

## 四、日程播报（顺序 + 状态复核）

```
帮我播报今天的日程：
1. 读取今天的日程（全部，不要筛选）
2. robot_list_locations 确认地点后导航到客厅
3. robot_status 确认导航已启动
4. 逐条用 robot_speak 播报，格式："第X项，主题，时间XX"
5. 播完说结束语
6. 每步都用 robot_status 复核后再进入下一步
字段缺失就省略，不要编造内容。
```

## 五、停止跟随（重要）

跟随是特殊状态，`robot_stop_patrol` 停不掉它。明确这样说：

```
让机器人停止所有移动。用 robot_move 的 moveId=5 完全停止，
不要用 robot_stop_patrol（停不掉 AI 跟随）。
停止后用 robot_status 确认已停下。
```

## 六、回桩充电（跟随后的正确顺序）

```
让机器人回去充电。注意顺序：
1. 如果正在跟随，先 robot_stop_patrol 停掉跟随任务
2. 再 robot_go_home(startUp=true)
3. 每30秒 robot_status 轮询，直到显示充电中且任务空闲，最多6次
4. 满电时充电状态可能不明显，如实告诉我，不要强行判断成功
```

## 七、多机器人分工

```
客厅的 EBO 去客厅拍张照片，卧室的 EBO 播报"该睡觉了"。
两台机器人用配置里不同的 server 名区分，分别确认状态。
```

## 八、智能家居联动（跨 MCP）

```
有人进门时（门窗传感器检测开关变化）：
1. EBO 导航到客厅，用 robot_status 确认
2. 检测人，识别到人名就带名字欢迎，没有就播通用欢迎语
3. 打开客厅灯（失败重试3次）
4. robot_follow 启动跟随
5. 播报后 robot_play_music 播放轻音乐
6. 程序退出时：停音乐(controlType=4) + 完全停止(moveId=5) + 关灯
```

---

## 写好提示词的四条经验

1. 先确认地点再导航：几乎所有真实项目第一步都是 `robot_list_locations`，避免猜名字
2. 每一步都要复核：明确要求 AI 用 `robot_status` 确认，不要凭返回 OK 判断物理执行
3. 循环和等待要有上限：叫早 10 轮、回桩 6 次、导航 120 秒——防止挂死
4. 给失败明确的退路：告诉 AI "检测不到人就跳过后续直接回桩"，而不是无限重试
