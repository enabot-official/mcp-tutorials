# 零基础：复制一段提示词，让 AI 带你做

这一页给完全没接触过 MCP 的人。你不需要懂技术，甚至不需要分得清「AI 模型」和「AI Agent」——那正是下面第一段提示词要帮你的。

**你唯一要会的是：打开一个 AI 助手，把文字复制粘贴进去，然后回答它的问题。**

做法只有三步：

1. 打开一个 AI 助手（本库实测用的是 WorkBuddy，见[选哪个 AI 助手](#先选一个-ai-助手)）
2. 复制下面某一节的**整段提示词**（代码块右上角有复制按钮），粘贴到对话框发送
3. 它会一步一步问你、告诉你做什么。你照着回答、照着做就行

> 这些提示词把本来要查文档、改配置、记工具名的活都交给 AI 了。你不用读那些技术文档；缺什么它会主动问你，不会让你猜。

## 先选一个 AI 助手

| 你想做的事 | 用哪种 AI 助手 |
| --- | --- |
| 连接机器人、发出指令、做三个项目 | 大部分 AI 助手都行，本库实测用 WorkBuddy |
| 看机器人的实时画面和声音（RTSP） | **必须用在你自己电脑上运行的助手**（如 WorkBuddy）。网页版/云端助手跑在别人的服务器上，进不了你家的 Wi-Fi，看不到机器人 |

如果你还没装，推荐先装 WorkBuddy——本库所有内容都在它上面验证过。下面提示词里提到的「配置文件」「自检脚本」，AI 助手会自己处理，你不用管。

## 30 秒扫盲：模型、Agent、MCP 是什么

把下面这段整段复制给 AI 助手，它会用大白话讲给你听：

```
请给我上一堂 30 秒的入门课。我是一个完全不懂技术的普通人，请遵守：
- 全程用大白话，不要出现英文缩写；必须说的时候，立刻用生活里的例子解释
- 每个词最多讲三句话
- 讲完问我哪里没听懂，没听懂就换一个更好的比喻再讲一遍

请解释这三个词：
1. AI 模型（就是 ChatGPT、豆包这类 AI 背后那个"大脑"）
2. AI Agent（我平时聊天、下指令的那个 AI 助手）
3. MCP（一种让 AI 助手能操作真实设备的方式）

最后用一句话说明：它们和"让我用说话的方式控制家里的 EBO 机器人"有什么关系。
```

## 提示词 1：连接你的机器人

**你要准备的**：在「一宝机器人」APP 的「MCP接口开放」页里找到令牌和接入地址。只需要这两样，别的都不用管。

把下面整段复制给 AI 助手：

```
你现在是我的「EBO 机器人配置向导」。我完全不懂技术，请遵守三条：
- 全程大白话，不用术语；要用就立刻用一句话解释
- 一次只问我一件事，我答完你再问下一件
- 缺任何信息就主动问我，不要猜，不要编造地址或令牌

你的任务是帮我连上 EBO 机器人，并确认真的连上了。按这个顺序带我做：

第 1 步 · 拿令牌和地址
告诉我打开「一宝机器人」APP 的哪个页面（叫「MCP接口开放」）能找到令牌和接入地址，让我复制后发给你。令牌是一串以 ebo_mcp_ 开头的字符。

第 2 步 · 写配置
我用的 AI 助手是 WorkBuddy。请你把连接信息写进本机的 ~/.workbuddy/mcp.json：
- 服务名用 ebo-robot
- 地址末尾拼接 /api/v1/mcp
- 令牌放在 Authorization 头里，写成 Bearer <令牌>
- 如果文件里已经有别的服务，只增加这一项，不要删别的内容
- 不要把令牌打印到屏幕、日志或任何回复里

第 3 步 · 真的验证一次
写好后，请你直接做两件事：列出当前可用的 MCP 工具，再调用只读的 robot_status 看机器人有没有真实返回。
- 工具能列出、robot_status 有返回：用大白话告诉我连上了，现在我能让它做什么
- 任何一步失败：按失败类型给我一个具体的检查动作（网络不通 / 令牌不对 / 工具没加载 / 机器人离线），一次只说一个
- 如果我本地已经放了教程仓库，也可以运行 examples/00-connection-check/check_connection.py 做更完整的自检

每做完一步用一句话确认，再进入下一步。结束时用三句话总结：我做了什么、现在能做什么、下一步可以玩什么。
现在开始第 1 步。
```

## 提示词 2：看实时画面和声音

**你要准备的**：确认你和机器人连的是同一个 Wi-Fi，并在 APP 里打开 RTSP 开关拿到局域网地址。

> 这是最容易卡住的一关：如果你用的是网页版 AI，它运行在别人的服务器上，进不了你家 Wi-Fi。请换成本机运行的 WorkBuddy 再试。

把下面整段复制给 AI 助手：

```
你现在是我的「EBO 音视频向导」。我完全不懂技术，请全程说大白话，一次只问我一件事，缺信息就问，不要猜地址或 IP。

你的任务是让我在 AI 助手这里看到 EBO 机器人的实时画面、听到它的声音。按顺序带我做：

第 1 步 · 确认 AI 助手在哪运行
问我：我现在用的 AI 助手，是装在我自己电脑上的，还是网页/手机 App 里的云端服务？
- 如果是本地电脑上的（例如 WorkBuddy），继续
- 如果是云端网页版，明确告诉我：云端服务在别人的服务器上，进不了我家的局域网，看不了机器人画面；需要换成本机运行的 AI 助手再继续

第 2 步 · 同一 Wi-Fi
问我运行 AI 助手的电脑和 EBO 是不是连着同一个 Wi-Fi；不是就告诉我怎么改成同一个。

第 3 步 · 拿 RTSP 地址
告诉我 APP 里哪里打开 RTSP / 局域网视频流开关，打开后会显示一个局域网地址，形式类似 rtsp://<机器人IP>:554/main0。让我把这个地址发给你。

第 4 步 · 验证
拿到地址后，用本地工具（如 ffprobe）确认能否连上、是否带视频和音频轨。
- 能连上：用大白话告诉我现在可以看画面听声音了，并给出最简单的观看/使用方法
- 连不上：一次给我一个排查动作（不在同一 Wi-Fi / RTSP 开关没开 / IP 写错 / 被防火墙拦）

重要：RTSP 地址里有我家设备的内网 IP，属于隐私信息。只在本地验证和使用，不要把它写进任何公开页面、日志或发给第三方。

每步做完用一句话确认，再进入下一步。现在开始第 1 步。
```

## 提示词 3：直接做出三个项目

**你要准备的**：什么都不用，先想好做哪个。AI 助手会问你缺什么。

把下面整段复制给 AI 助手：

```
你现在是我的「EBO 项目向导」。我完全不懂技术，请全程大白话，一次只问我一件事，缺信息就主动问，不要猜、不要编造。

先问我三个项目里想做哪个：
A. 早间播报——每天早上让机器人念日程、叫人起床
B. 开门迎宾——有人进门时机器人过去欢迎、开灯、放音乐
C. 语音助手——让机器人听我说话并回应（目前只能做到"听见并转成文字"，完整对话还没跑通，要如实告诉我）

我选好后，按下面对应流程一步步带我做，每步做完用一句话确认结果，再进入下一步。任何一步缺少信息（比如日程从哪来、地点叫什么、米家账号、Wi-Fi 情况），就先问我，不要假设。

【A 早间播报】
1. 问我日程放在哪里（日历 App / 表格 / 手动输入），需要时让我提供读取方式
2. 问我想让机器人在家里哪个地点播报（例如"客厅"），并提醒我这个名字必须和 APP 地图里的地点名一模一样
3. 让我先用一条简单指令确认机器人能听懂（例如让它说一句话）
4. 引导我按这个顺序做：读取日程 → 确认地点存在（robot_list_locations）→ 导航过去（robot_navigate）→ 用 robot_status 确认到位 → 逐条播报（robot_speak）
5. 提醒我：机器人不会每步回报"做完了"，必须用 robot_status 确认后才能继续；叫早循环最多 10 轮，没人就回桩
6. 问我是否要设置每天定时运行；要的话告诉我怎么在 WorkBuddy 里设置定时任务

【B 开门迎宾】
1. 先问我有没有米家账号和门窗传感器；没有就告诉我需要先准备什么
2. 问我机器人和传感器是否在同一局域网，播报地点叫什么（须与 APP 地图一致）
3. 引导我把 EBO 和米家分别作为两个 MCP 服务接入
4. 触发流程按顺序：门磁变化 → 机器人导航到门口/客厅并用 robot_status 确认 → 检测人、识别到人就带名字欢迎 → 开灯 → 跟随 → 播放轻音乐
5. 关键提醒：停止跟随要用 robot_move 的 moveId=5，robot_stop_patrol 停不掉跟随；退出时要停音乐、完全停止、关灯
6. 如实告诉我哪些环节需要真实硬件才能测

【C 语音助手】
1. 先带我完成 RTSP 连通（确认本机 AI 助手、同一 Wi-Fi、拿到 RTSP 地址），可以让我用提示词 2
2. 告诉我目前实测到哪一步：音频能转成文字；端到端语音闭环还没跑通，原因是 8kHz 音质和远场噪声
3. 引导我运行仓库 examples/03-voice-assistant/ 里的脚本；如果我手上没有这些脚本，请你直接帮我写好放到本机，缺依赖就提示我安装
4. 每一步都用实际输出验证，不要只看命令返回 OK

结束时用三句话总结：我做了什么、现在能做什么、哪里需要继续。现在开始问我选 A / B / C。
```

## 提示词 4：出问题时贴这段

**你要准备的**：把出问题的现象用你自己的话写在提示词后面一起发。

```
你现在是我的「EBO 排错向导」。我完全不懂技术，请全程大白话，一次只问我一件事。

我会告诉你现在遇到的现象。请按下面顺序帮我排查，每查一项先告诉我怎么判断，再根据我的回答缩小范围，直到找到原因：
1. 配置文件在不在、服务名是不是 ebo-robot、地址是不是以 /api/v1/mcp 结尾
2. 网络能不能连到接入地址
3. 令牌是否正确、是否过期（不要让我把令牌打印出来）
4. 工具列表有没有加载出来、数量是多少
5. 机器人是否在线、电量和当前状态
6. 具体动作失败：导航没到位、拍照没图、跟随停不下来、播报没声音等

每找到一个问题，就给我一个明确、只做一件事的修复动作；修完让我回来继续。如果按顺序都查完还没解决，如实告诉我，并把现象整理成一段可以反馈给官方的描述。

现在请告诉我：你遇到了什么现象？
```

## 用之前先知道这几件事

- **令牌像家门钥匙**：只发给你信任的、在你自己设备上运行的 AI 助手。不要贴到陌生网站或来路不明的 AI 服务里。AI 应该帮你写进本机配置，而不是把它显示在聊天记录里。
- **机器人会真的动**：导航、跟随、开灯都是真动作。让它动手前先确认周围没人挡路、没有易碎物。
- **不同 AI 助手、不同模型的表现会不一样**：配置入口、说话方式、能不能改本机文件都有差异。上面提示词里的技术思路是一样的；如果某个助手做不到，换 WorkBuddy 或让它换个方式继续。
- **「下发成功」不等于「执行完成」**：好提示词都会要求 AI 用 `robot_status` 复核，别省掉这一步。
- **本库所有项目都在 EBO MAX 上实测**：目前只有 EBO MAX 和 EBO Air2 Plus 支持 MCP，详见[支持机型](../../README.md#支持机型)。
